# Radar tecnológico

Repositorio de informes diarios para preparar contenido de tecnología de consumo.

## Para Claude: lectura rápida

1. Abre **solo `RADAR_ACTUAL.md`** para trabajar con el informe vigente.
2. No recorras `historial/` salvo que el usuario pida comparar días o detectar evolución.
3. Trata las fechas, métricas y enlaces como datos fuente: no inventes cifras ni conviertas tendencias antiguas en noticias nuevas.
4. Distingue noticias confirmadas en las últimas 24 horas de temas/tendencias que siguen teniendo recorrido.
5. Usa el radar como materia prima para proponer vídeos originales; no copies los vídeos enlazados.

## Estructura

- `RADAR_ACTUAL.md`: informe más reciente. Se reemplaza cada día.
- `historial/AAAA-MM-DD.md`: copia fechada de cada informe diario.

## Criterios del radar

- Zona horaria: Europe/Madrid.
- Cadencia prevista: diaria a las 07:00.
- Noticias: exclusivamente publicadas/anunciadas en las 24 horas anteriores al cierre del informe.
- Vídeos: TikTok, Instagram Reels y YouTube Shorts; prioridad a España y al contenido en español.
- Selección de oportunidades: equilibrio aproximado 50 % vídeos con rendimiento excepcional y 50 % creadores emergentes.
- Métricas: incluir solo datos verificables y señalar lo que no se haya podido comprobar.

## Regla de integridad

Si una noticia, fecha, métrica o vídeo no puede verificarse, debe marcarse como no verificado o excluirse. Es preferible un informe más corto a rellenarlo con datos dudosos. Si la publicación en GitHub falla, el informe no debe darse por publicado.
